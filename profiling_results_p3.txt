 BENCHMARK DE CPU — Pipeline Comprimir + Cifrar RC4
=======================================================

  A. Clásico (plano)           : 237000 bytes (100%)
  B1. Solo Huffman             : 138561 bytes (58.5% del original)
  B2. Solo LZ77               : 29888 bytes (12.6% del original)
  C1. Huffman + RC4            : 138561 bytes (= B1; RC4 sin padding)
  C2. LZ77   + RC4            : 29888 bytes (= B2; RC4 sin padding)

── TIEMPO DE CPU (CLOCK_PROCESS_CPUTIME_ID) ────────
  A. Clásico (memcpy a buffer):              0.0015 ms
  B1. Huffman (compresión sola):             2.1565 ms
  B2. LZ77 (compresión sola):               53.7238 ms
  C1. Pipeline Huffman + RC4:             
      ├── Compresión Huffman:                 2.1331 ms
      ├── Cifrado RC4 (AISLADO):              0.5139 ms
      └── TOTAL pipeline:                     2.6470 ms
  C2. Pipeline LZ77 + RC4:                
      ├── Compresión LZ77:                   54.8202 ms
      ├── Cifrado RC4 (AISLADO):              0.0999 ms
      └── TOTAL pipeline:                    54.9201 ms

── ANÁLISIS DE IMPACTO ──────────────────────────────
  Overhead RC4 sobre Huffman   : +0.5139 ms (19.4% del pipeline)
  Overhead RC4 sobre LZ77      : +0.0999 ms (0.2% del pipeline)
  Reducción I/O (Huffman+RC4)  : 41.5% menos bytes al bus de disco
  Reducción I/O (LZ77+RC4)     : 87.4% menos bytes al bus de disco

── CONCLUSIÓN ARQUITECTÓNICA ────────────────────────
  Orden correcto: COMPRIMIR primero, CIFRAR después.
  RC4 genera entropía ~8 bits/byte: si cifráramos primero,
  los datos serían pseudoaleatorios → Huffman y LZ77 no
  encontrarían patrones → compresión nula o negativa.
  El overhead de RC4 (0.5139 ms) compra seguridad total
  con un archivo 41.5% más pequeño en disco.
